# @repo/db

## Responsibility and non-goals

`@repo/db` owns the postgres.js/Drizzle client boundary, schema exports, migrations, grouped
query entry points, and database test helpers. T03 provides the process-wide default client,
isolated client creation, transaction support, and the Better Auth core schema and migration.

It does not own Auth or Billing workflows, run migrations during application startup, implement
a generic repository layer, or add product queries in T03. The existing query and testing
subpaths remain reserved boundaries until their owning tickets implement them.

## Dependencies

Allowed dependencies: Drizzle ORM/Kit, postgres.js, `server-only`, `@repo/config`, the Better
Auth CLI for schema generation, and type/build tooling.

Forbidden dependencies: `@repo/auth`, `@repo/billing`, `@repo/email`, UI packages, provider
SDKs, and app internals. Auth may depend on DB; DB must never reverse that dependency.

## Public exports

| Export | Target | Purpose |
| --- | --- | --- |
| `@repo/db/client` | `src/client/index.ts` | Default/isolated Drizzle clients and transaction helpers. |
| `@repo/db/schema` | `src/schema/index.ts` | Server-only Better Auth core schema exports. |
| `@repo/db/queries/users` | `src/queries/users/index.ts` | Reserved user-query boundary; no concrete T03 queries. |
| `@repo/db/queries/billing` | `src/queries/billing/index.ts` | Reserved billing-query boundary; no concrete T03 queries. |
| `@repo/db/queries/example` | `src/queries/example/index.ts` | Reserved example-query boundary; no concrete T03 queries. |
| `@repo/db/testing` | `src/testing/index.ts` | Test-only database context boundary. |

## Minimal usage

```ts
import { db, withTransaction } from '@repo/db/client';
import { user } from '@repo/db/schema';

await withTransaction(db, async (transaction) => {
  await transaction.select().from(user);
});
```

Use `createDatabaseClient()` for tests, scripts, or deployments that need an isolated pool.

## Placement rules

`src/schema/core.ts` is generated by the Better Auth CLI and must not be edited manually. Put
custom tables in separate schema files and reusable named queries under `queries/<feature>/`.
Keep client construction in `client/`; do not add table-per-class repositories. Production code
must not import `@repo/db/testing`.

## Security and transaction notes

Every runtime export is server-only. The default client is a Node-process singleton configured
by `DATABASE_URL` and `DATABASE_POOL_MAX`, with prepared statements disabled for transaction
pooler compatibility. User-scoped queries must include a trusted `userId` predicate. DB exposes
transaction mechanics only; atomic credit and billing workflows belong to `@repo/billing`.

## Validation commands

```bash
pnpm --filter @repo/db typecheck
pnpm --filter @repo/db auth:generate
pnpm --filter @repo/db drizzle:migrate
```

Schema generation and migration commands require their documented database environment.
