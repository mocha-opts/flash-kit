---
title: Customization
description: Customize the brand, Catalog, templates, locales, navigation, and Fumadocs theme.
---

The starter keeps product-specific choices in explicit seams. Change those seams instead of
forking the runtime or adding a second configuration system.

## Brand and metadata

- Set `NEXT_PUBLIC_APP_NAME` in Web environment configuration.
- `@repo/config/app` derives product identity and enabled OAuth flags from the validated Web
  environment; it has no second app-local config file.
- Update the Web metadata and brand components under `apps/web`.
- Update `apps/docs/app/layout.tsx` metadata and `apps/docs/lib/layout.shared.tsx` for the docs
  title, GitHub URL, and navigation. The starter does not hardcode an Application URL in the
  production docs navigation.

The Docs app intentionally does not read Web provider secrets or import Web business packages.

## Billing Catalog

Edit `packages/billing/src/config/billing-catalog.ts` to add or rename a plan, then update the
server environment example with the selected Provider IDs. Keep:

- `id`, `kind`, `interval`, features, limits, and integer Credit quantity as product semantics.
- `cost` and `currency` as display-only values.
- Provider Product/Price IDs as selected deployment inputs.

Checkout must continue to use the Provider IDs, and webhook fulfillment must continue to use signed
Provider amounts/statuses. Update the Billing docs whenever the Catalog changes. Do not create
local Product, Price, Customer, Subscription, or Entitlement tables to mirror a Provider.

## Email templates

Add localized React Email templates under `packages/email/src/templates`, copy under
`templates/messages`, and a typed semantic sender under `senders`. Export it through
`@repo/email/server`. Keep HTML/plain text rendering inside the email package and do not import
`@repo/ui` or browser components. See [Email](/docs/email/templates-and-senders).

## Locale

The product's locales are `en` and `zh-CN`; English has no prefix and Chinese uses the
`/zh-CN/...` prefix (`localePrefix = 'as-needed'`). Add message keys to both Web message trees and
keep route paths generated by `@repo/i18n/navigation`. Docs content is currently English-only so
architecture contracts remain easy to search; Chinese repository guidance remains under root
`docs/`.

## Navigation

Docs page ordering is content-owned. Edit `apps/docs/content/docs/meta.json` or a section's
`meta.json`; page titles/descriptions live in MDX frontmatter. Shared nav links live in
`apps/docs/lib/layout.shared.tsx`, where Fumadocs `DocsLayout` consumes `source.getPageTree()`.
Search links in `RootProvider` and the `/api/search` handler must remain aligned.

## UI tokens

`apps/docs/app/globals.css` imports the official Fumadocs Tailwind 4 preset and overrides the
semantic `--color-fd-primary` and ring tokens for the Flash Kit brand. Keep overrides semantic and
accessible in both light and dark themes. For product UI, use `@repo/ui` narrow exports and its
Tailwind/CVA tokens; do not make Fumadocs depend on product business packages.

## Fumadocs content pipeline

The Docs app uses the official layers:

```text
MDX under content/docs
  → fumadocs-mdx macro in lib/source.ts
  → fumadocs-core loader(baseUrl: /docs)
  → Fumadocs DocsLayout + DocsPage
  → /api/search powered by createFromSource
```

`apps/docs/next.config.ts` wraps the Next config with `createMDX()`. New MDX pages need a title
frontmatter field and must be listed in the relevant `meta.json` when explicit ordering is
desired. Run the Docs production build after changing content or the source adapter.
